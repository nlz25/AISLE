# Architecture and performance

## Build boundary

The Python entry point `scripts/build_site.py` imports independent page renderers from `src/sitegen/pages/`. Shared layout and UI live under `components/`; score and network metadata remain in `data/`. The generator uses only the Python standard library. The home page loads `network.css` after the shared theme and entrance styles, keeping the research map's layout and responsive rules together.

`public/` contains delivery-ready static assets. The build copies these into a clean `dist/`, combines the base/theme CSS, copies the entrance CSS and browser modules, and renders three English pages. A content-derived version updates stylesheet and module URLs, including dynamic imports. `dist/build.json` records that version.

GitHub Actions validates each pull request. A successful build on `main` uploads only `dist/` to Pages. Source, originals, local tools and documentation are excluded. The earlier root-level generated pages and `/zh/` pages have been removed.

## Browser lifecycle

- `navigation.js`: mobile menu and page visibility state on every page.
- `main.js`: chooses the appropriate enhancements and defers expensive work.
- `portal.js`: hash-driven entrance/network navigation, focus and Back/Forward. Global pointer distance smoothly drives hand extension, forearm rotation and atmospheric light through one progress value. The response loop runs only while changing. Keyboard and touch can enter directly; reduced motion fixes the hand at contact. Activation blooms and crossfades, with a fade fallback.
- `portal-hand.js`: seven rigid joint controls over eight views of one assembled painting. The wrist and three index phalanges follow staggered pose curves; the curled fingers have small secondary rotations. `hand.py` clips each view from the shared image and masks those areas out of the palm. The index root's outer bearing remains on the palm while its outgoing shell rotates; the middle hinge's whole top cap belongs to the moving middle layer to prevent floating slivers. At contact the layers reconstruct the complete painting, retaining the gently bent gesture traced from the original PNG. A local SVG reflection follows scene-light strength independently of pose, using a radial amber filter whose final atop composite preserves the original alpha. No duplicate translucent edge can mask the sunrise behind the fingertip. No independent animation loop or physics library is added. The original supplied hand remains the failed-image and script-free fallback.
- `portal-scene.js`: shared Earth projection, contact placement, projected radius and light-strength uniform. The fingertip at full extension and the sunrise coincide on the projected horizon. In tall tablet windows the contact moves down the limb to keep its horizontal position at or below 78% of the viewport width. CSS uses the same radius to occlude the light's lower half along the curved planet, including after resize and with centered cover-cropped fallback posters.
- `globe.js`: optional Globe.gl Earth with separate surface, clouds and atmosphere. Initial and HD maps share the same imagery and packed cloud format; terrain bump is enabled before the first visible frame, including after Globe.gl's initial custom-map reset. HD changes texture resolution without recompiling the material. Initialization follows artwork paint and an idle opportunity. During normal loading, the globe host stays hidden without a poster; synchronous camera/crop setup and a successful complete draw precede its reveal. Reduced-motion and data-saving visits use a responsive poster of the current scene. A later change to reduced motion stops automatic rotation while preserving manual controls.
- `globe-flare.js`: official Three.js Lensflare with a compact procedural source and the example aperture texture, sharing the Earth loop and camera-relative sunrise position. A small depth probe handles occlusion. The vendored element material adds RGB while preserving canvas alpha, preventing an optical footprint from masking the background. Optional texture loading is independent of the first Earth frame; failures enable a smooth CSS source.
- `research.js`: tabs, model details, score ordering/tooltips and study statistics. Loaded when the research view is entered, or on the leaderboard page.
- `network.js`: regional research-direction selection, anchored film-card placement, on-demand film player and overlapping decorative meteors between randomly selected peer regions. A ResizeObserver keeps the card beside the selected pin, avoids pins and labels and reserves any needed space below the proportional map on narrow screens. Transfers are scheduled at independent random intervals, with at most five active meteors (four for the current regions), no duplicate active pairs and no persistent map paths. Loaded only on entry to the research network.
- `counter.js`: optional, nonblocking entrance click counting. The Cloudflare service and its separate checks are documented in [Portal click counter](counter.md).

The entrance hand slides in from the left with a small rotation and decelerates directly to its resting position in 780 ms once the artwork has decoded. This CSS animation runs on the artwork wrapper independently of the pointer-driven arm transform and nested finger joints. Reduced motion fixes every joint at the extended contact pose. The title, quotation, attribution and tagline fade upward in sequence. Reduced motion skips these animations; without JavaScript the supplied complete hand remains visible and static.

The research section starts hidden; lazy images are not requested during entrance display. A noscript style exposes the server-rendered research content when JavaScript is disabled. Videos keep `preload="none"` and receive their source only after a visitor opens the player.

Unavailable WebGL, failed initialization and context loss also show the current-scene poster. Context restoration reveals the live globe only after another complete draw. The same posters appear without JavaScript. The old `robot-earth.webp` artwork has no runtime references, and the default centred blue sphere is never exposed.

## Performance choices

- WebP delivery copies preserve the supplied/generated artwork; originals stay in `design/originals/`.
- Locally served WOFF2 replaces TTF. The header logo and favicon are sized for their rendered uses.
- The first complete Earth uses a 179,922-byte 2K surface, a 101,680-byte 1K packed terrain/cloud map, a 24,636-byte global night map and a 25,016-byte land/ocean mask (331,254 bytes total). The initial maps are downsampled from the same originals as the optional 4K maps, so colour, terrain and clouds remain consistent during HD loading. The supplied 226 KB hand remains available as fallback; the articulated version adds one 186,018-byte WebP painting. Eight SVG views share this image without loading separate part textures. Revision 4 retains the satin-silver links and uses authored cool environmental lighting. A filter on the existing geometry adds a bounded, textured warm reflection near contact, preserving the original alpha with an atop composite; the whole-hand CSS drop shadow is removed to avoid casting a false dark patch onto Earth. The reflection uses the existing portal update loop and requests no additional image. Responsive fallback assets `assets/globe/earth-poster.webp` and `earth-poster-mobile.webp` are transparent captures of Earth alone; the contact sunrise is a shared CSS layer. Normal WebGL loading does not request the posters. Desktop visits on fast connections can load the existing 4K surface and packed cloud/terrain maps after three visible seconds. These optional requests are aborted when the entrance or tab is hidden. Narrow screens and slower connections keep the same smaller maps and material features.
- Night imagery is generated as a 2K/4K/8K WebP pyramid from the original 8K map. Each 512-pixel tile includes an eight-pixel neighbouring-image gutter. The 1K global base stays visible at all times. Only visible night-side regions request higher detail, selected by projected texel density at most five times per second. Desktop fast connections can reach 8K detail; mobile and 3G visits stop at 4K, while 2G uses the base alone.
- At most two tile requests run concurrently. Manual dragging pauses new requests and aborts outdated work; releasing the pointer selects the new view. A 16-slot GPU atlas uses least-recently-used eviction outside the desired set. Parent/base imagery remains visible while children load and fade in over 450 ms (immediate under reduced motion). Cached files use content-addressed paths, and source imagery is never deployed. The complete pyramid is about 2.03 MB, but each visit requests only selected tiles.
- Tile imagery is sampled in the existing Earth material, keeping three scene draw calls. An indirection texture and explicit sampling derivatives avoid sampling jumps at tile boundaries; mipmaps, gutters and anisotropic filtering preserve motion stability. Atlas allocation is bounded at 2112 x 2112 pixels plus mipmaps (about 22.7 MiB for RGBA8), independent of how many regions a visitor has seen. A small global base and page table add roughly 2.7 MiB. Unsupported graphics, failed requests and eviction fall back through available parents to the global base.
- Globe.gl 2.46.2 and Three.js 0.183.2 are pinned in `scripts/globe-vendor/package-lock.json`, with one shared Three.js instance and the official Lensflare addon. A guarded build transform changes only the optical element blending: RGB is additive while destination alpha is preserved. Its source markers deliberately fail the build if a Three.js upgrade needs review. The self-contained local ES module is approximately 1.85 MB uncompressed / 527 KB gzip (level 6). It is fetched only with the optional globe module, never from a runtime CDN. Ordinary builds do not run npm. `npm ci --ignore-scripts` then `npm run build` in that directory reproduces the bundle and dependency licenses. The build's content hash includes the vendor module.
- Earth rendering has a 4.5-million-pixel budget, with DPR capped at 2 on desktop and 1.5 on narrow screens. Automatic rotation is capped at 20 fps, with a 30 fps ceiling during dragging. Globe.gl's own animation loops are paused; the site submits surface, cloud, atmosphere and optical flare draws through one visibility-aware loop. Idle Earth uses three draws. An active Lensflare adds its 16 × 16 occlusion probe, restoration, four optical sprites and transparent container, bringing the total to ten draws. Only the 4,822-byte aperture texture is requested; a 128 × 128 Gaussian source is generated in memory. The broad diffraction bitmap is archived. Preserving canvas alpha prevents low-intensity light from leaving an opaque dark disc. The CSS fallback uses the same smooth source profile and aperture masks. These effects increase GPU work; no full-screen postprocessing pass is added.
- The scene is an illustrative orbital composition with a standard PBR surface, height/roughness maps, night-side emission, separate clouds and an atmosphere shell at 1.06 times Earth's radius. A soft key light and low blue ambient intensity (0.025) retain terrain depth. The dusk fill has a 0.14 angular width and 0.45 gain; lower night-side surface and atmospheric scattering preserve a darker hemisphere with a smooth terminator; city lights fade through that same lighting transition. Blue limb haze and the localized warm contact respect surface colour headroom. A camera-local contact direction aligns this warmth with the CSS sunrise. This is a visual lighting model, not a physical atmospheric or astronomical simulation, and retains three scene draws without HDR render targets or full-screen scattering passes.
- Land/ocean classification is a dedicated lossless mask present from the first frame. Ocean roughness is 0.5 and land roughness is 0.9, with soft coast coverage. Water uses dielectric F0 0.0204, land 0.04; both remain non-metallic. Water reflections are soft and concentrated near the contact. The off-source specular lobe is attenuated before display rather than compressed into a broad grey plateau. Terrain bump normals are suppressed over water. HD loading replaces colour, terrain and cloud detail without replacing this mask or switching the material's reflection rules. The mask is derived from the packed source's green channel by `build_land_mask` in `scripts/optimize_assets.py`, and its bytes participate in the build asset version.
- Zoom, pan, automatic damping and hover picking are disabled. Manual rotation remains available while automatic rotation is paused. The site uses no geographic data layers, postprocessing passes or shadow maps for this entrance.
- The Earth and map stop rendering outside their view and when the document is hidden. CSS animation also pauses in background tabs.
- Entrance light layers change opacity and gradient spread with proximity. Their scene container does not create a stacking context, so screen blending sees the Earth canvas rather than a transparent intermediate group. Individual arm/light stacking levels preserve the drawing order. Their curved masks keep a shallow sunrise cap attached to the horizon; the hand moves through transforms. The response sleeps after settling. A shared uniform broadens local surface warmth, ocean reflection and atmospheric scattering in the existing three Earth draws. Mobile drops the full-screen grain layer, and reduced motion holds the hand still.

These are asset and rendering-budget measurements, not a claim about visitor loading time on a particular network. Validate on the intended devices before changing these budgets.

## Checks

`make check` builds all pages, checks local resources and fragment links, ARIA control targets, study-score aggregation, cohort coverage, institution/media records, English-only output, CSS/module references and the deployment boundary. It also checks JavaScript syntax. The checker validates all 168 night tiles against the manifest, the 40 KB global-night-base budget, the 4 MB complete-pyramid budget, the existing 1 MB portal-media / 2 MB optional surface-detail budgets, the 350 KB optional hand-atlas budget, and the 600 KB gzip dependency-bundle budget.

`scripts/build_hand_assets.py` reproduces the hand's shared WebP painting,
eight SVG part views and `design/hand-rig-preview.html` from the preserved
generated PNG. This optional authoring tool needs Pillow; ordinary site builds
still use only the Python standard library. The offline preview embeds the
actual joint controller and supports a pose slider and comparison with the
original PNG's final gesture. The ring and little fingers
remain one rear group in this prototype; fixed raster lighting and occlusion
limit it to the authored side view and modest movements.

Regenerate the pyramid with `python scripts/build_night_tiles.py` after installing
`requirements-dev.txt`. The preserved source is
`design/originals/globe/earth-night-8k.jpg`. The recipe hashes source bytes,
tile size, gutter and quality into immutable tile paths. The site build includes
the manifest in its asset version, so regenerated imagery invalidates browser
module and manifest caches. No authoring dependency or image processing runs
in the visitor's browser.

Browser QA covers loading and refresh without placeholder flashes, first-frame cropping, context recovery, responsive posters, entry/back navigation, globe controls, institution selection, video playback, cohort/category changes, model detail expansion, mobile menus and narrow-screen overflow. Honor reduced motion and retain static fallbacks for unavailable WebGL.
